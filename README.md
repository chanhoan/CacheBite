## 빠른 시작

> **서명되지 않은 베타 버전 안내:** 현재 CacheBite 빌드에는 코드 서명이 적용되어 있지 않습니다. Windows에서는 SmartScreen 경고가 표시되며, macOS에서는 격리 속성을 해제하기 전까지 Gatekeeper가 서명되지 않은 DMG 실행을 차단합니다. Linux에서는 AppImage를 사용하며, 시스템에 WebKitGTK 4.1이 설치되어 있어야 합니다.

[GitHub Releases](https://github.com/chanhoan/CacheBite/releases)에서 최신 베타 버전을 다운로드하세요.

| 플랫폼 | 설치 파일 | 참고 사항 |
| --- | --- | --- |
| Windows | MSI 및 NSIS 설치 프로그램 | 업그레이드할 때 기존 베타 버전 위에 그대로 설치하세요. |
| macOS | 서명되지 않은 검증용 Universal DMG | Apple Silicon과 Intel에서 모두 사용할 수 있는 단일 파일입니다. 현재는 검증 목적으로만 제공되며 아직 공증되지 않았습니다. |
| Linux | AppImage | WebKitGTK 4.1과 관련 데스크톱 필수 구성 요소가 필요합니다. |

설치하기 전에 다운로드한 파일의 체크섬이 `SHA256SUMS.txt`와 일치하는지 확인하세요. 플랫폼별 설치 방법과 베타 버전 문제 제보 지침은 [docs/beta-testing.md](docs/beta-testing.md)에서 확인할 수 있습니다.

직접 다운로드하는 과정은 일반적으로 처음 한 번만 필요합니다. `v0.1.0-beta.4`부터는 CacheBite 앱 안에서 새 버전을 확인하고 업데이트할 수 있습니다. 자세한 내용은 [업데이트](#업데이트)를 참고하세요. `v0.1.0-beta.3` 이하 버전에는 업데이트 기능이 없으므로, 한 번은 최신 빌드를 직접 설치해야 합니다.

### 처음 실행하기 전에

- Claude를 사용하려면 이 컴퓨터에서 Claude Code에 로그인되어 있어야 합니다.
- Codex를 사용하려면 `codex` CLI가 `PATH`에 등록되어 있고 로그인된 상태여야 합니다.
- 둘 중 하나만 사용해도 괜찮습니다. 하나의 제공자에만 로그인된 경우에도 CacheBite는 다른 제공자의 데이터가 있는 것처럼 표시하지 않고, 사용할 수 없는 상태임을 명확히 보여줍니다.

## CacheBite 사용법

1. CacheBite를 설치하고 실행합니다.
2. 데스크톱에 작은 펫이 나타납니다. 원하는 곳으로 드래그해 옮길 수 있으며, 위치는 디스플레이별로 저장됩니다.
3. 펫을 더블 클릭하거나, 펫에 포커스가 있는 상태에서 Enter 키를 누르면 사용량 패널이 열리거나 닫힙니다. 한 번 클릭하는 것만으로는 패널이 열리지 않습니다.
4. 펫을 마우스 오른쪽 버튼으로 클릭하면 `Show usage panel` 또는 `Hide usage panel`, `Hide pet`, `Quit CacheBite` 메뉴가 열립니다.
5. 패널에는 Claude와 Codex가 나란히 표시되는 대신 각각의 탭으로 제공됩니다. 각 탭에서는 세션 사용량과 주간 사용량을 원형 게이지로 확인할 수 있습니다. 현재 지원하는 제공자의 세션 사용량은 5시간 단위로 표시됩니다.
6. 다른 제공자의 사용량을 확인하려면 탭을 전환합니다.
7. 최신 사용량을 불러오려면 `Refresh now`를 클릭합니다. `Set as primary`를 클릭하면 펫의 링과 상태에 반영할 제공자를 선택할 수 있습니다.
8. `Settings`에서는 화면 모드, 기본 제공자, 펫, 말풍선, 알림, 보조 제공자 알림, 로그인 시 자동 실행 여부를 변경할 수 있습니다.

Windows와 Linux에서는 `Ctrl+Shift+H`, macOS에서는 `Cmd+Shift+H`를 누르면 어디서든 펫을 숨기거나 다시 표시할 수 있습니다. 펫을 숨기면 사용량 패널도 함께 닫힙니다. 이 단축키는 사용자가 변경할 수 없는 고정 단축키입니다. 다른 애플리케이션에서 이미 사용 중인 경우 CacheBite는 설정 화면에 충돌 사실을 표시하고 계속 실행됩니다.

앱에는 Tabby, Corgi, Momo 총 3종의 펫이 기본으로 제공됩니다. 선택한 펫과 기본 제공자는 서로 독립적입니다. 하나를 바꿔도 다른 하나에는 영향을 주지 않습니다.

링의 두 원형 게이지는 각각 세션 사용량과 주간 사용량을 나타냅니다. 펫의 기분은 기본 제공자의 사용량에 따라 달라지므로, 데스크톱에서 가장 중요하게 확인하고 싶은 제공자의 상태를 한눈에 볼 수 있습니다.

앱에 표시되는 상태는 다음과 같습니다.

- `Fresh`는 현재 사용량 정보가 최신 상태임을 의미합니다.
- `Stale`은 사용량 정보가 계속 표시되지만, 최신 상태로 간주하는 시간 범위를 지났음을 의미합니다.
- 제공자 계정에서 로그아웃했거나 제공자를 사용할 수 없는 경우, CacheBite는 사용량 데이터가 있는 것처럼 표시하지 않고 해당 상태를 보여줍니다.
- 패널 하단의 `Settings` 옆에 점이 표시되면 설치할 수 있는 새 버전이 있다는 의미입니다.
- Windows에서는 다른 애플리케이션이 전체 화면으로 실행되는 동안 CacheBite가 펫과 패널을 숨깁니다. 전체 화면을 종료하면 펫이 다시 표시되지만, 전역 단축키로 직접 숨긴 경우에는 그대로 유지됩니다. 다른 플랫폼에서는 전체 화면 감지가 작동하는 것처럼 처리하지 않고, 지원되지 않는 상태임을 표시합니다.

## 작동 방식

1. CacheBite는 컴퓨터에서 각 제공자의 사용량을 로컬로 수집합니다.
2. Rust에서 제공자별 응답을 공통 사용량 모델로 정규화합니다.
3. Svelte 렌더러는 정규화된 상태를 바탕으로 펫, 링, 패널, 설정 화면을 표시합니다.
4. 말풍선과 알림은 CacheBite의 원격 서비스가 아닌, 로컬에서 감지한 사용량 변화에 따라 작동합니다.

## 업데이트

CacheBite는 GitHub Releases에 게시된 업데이트 매니페스트를 확인하고, 서명된 새 빌드가 있으면 앱 안에서 업데이트를 안내합니다.

- 업데이트 확인은 자동으로 이루어집니다. 앱 실행 약 30초 후, 백그라운드에서 1시간마다, 그리고 사용량 패널을 열 때(최대 15분에 한 번) 확인합니다. 직접 확인을 실행하는 버튼은 없습니다.
- 새 빌드가 게시되면 패널 하단의 `Settings` 옆에 점이 나타납니다. 설정 화면에는 `Update available` 안내와 `Install and restart` 버튼이 표시됩니다.
- 설치를 시작하면 현재 플랫폼에 맞는 파일을 다운로드하고 서명을 검증한 뒤, 기존 빌드 위에 설치하고 CacheBite를 다시 시작합니다. 설정, 사용 기록, 설치된 펫은 그대로 유지됩니다.
- 어느 단계에서든 문제가 발생하면 설정 화면에 오류가 표시되며, 현재 실행 중인 빌드는 변경되지 않습니다. 언제든 릴리스를 직접 설치할 수도 있습니다.
- 업데이트 채널은 현재 실행 중인 빌드를 따릅니다. `0.1.0-beta.5`와 같은 프리릴리스 빌드에서는 베타 릴리스를 확인하고, 정식 빌드에서는 안정 버전만 확인합니다. 채널은 별도로 저장하지 않고 실행 중인 버전에서 결정하므로, 베타 참여 설정이 의도치 않게 계속 유지되는 문제는 없습니다.
- 앱 내 설치는 Windows에서 검증되었습니다. macOS와 Linux용 파일도 게시되고 서명되며 CacheBite가 설치를 시도하지만, 서명되지 않은 macOS 앱 번들을 교체하거나 실행 중인 AppImage를 갱신하는 과정은 아직 실제 하드웨어에서 검증되지 않았습니다.

렌더러는 업데이터와 직접 통신하지 않습니다. 업데이트 확인, 다운로드, 서명 검증, 설치는 모두 Rust 코어에서 처리하며, 패널에는 처리 결과만 전달됩니다.

## 개인정보 보호

> CacheBite는 제공자 인증 정보를 로컬에만 보관합니다. CacheBite 서버를 거쳐 전송되는 정보는 없으며, 렌더러에는 정규화된 상태만 전달됩니다.

- CacheBite는 별도의 클라우드 서비스를 운영하지 않습니다.
- 인증 정보 접근, 사용량 수집, 새로고침 일정 관리, 데이터 저장은 Rust 코어에서 처리합니다.
- Svelte 렌더러에는 정규화된 상태만 전달됩니다.
- CacheBite는 브라우저 쿠키를 읽지 않습니다.
- 제공자의 원본 응답, 계정 식별자, 인증 정보 경로는 로그나 스크린샷에 포함되지 않습니다.
- 인증 정보 파일은 읽기 전용으로 처리합니다.

## 베타 버전 상태와 제한사항

- 현재 베타 버전에는 코드 서명이 적용되어 있지 않습니다. 업데이트 파일에는 업데이터용 서명이 포함되지만, 이는 플랫폼 코드 서명과는 다릅니다.
- 릴리스 게시 과정에는 아직 수동 작업이 필요합니다.
- 앱 내 업데이트는 Windows에서 검증되었습니다. macOS와 Linux에도 서명된 파일이 제공되지만, 해당 플랫폼의 설치 과정은 아직 검증되지 않았습니다.
- `v0.1.0-beta.3` 이하 버전은 자체 업데이트를 지원하지 않으므로 한 번은 직접 새 버전으로 교체해야 합니다.
- 전체 화면 감지는 현재 Windows에서만 지원합니다. macOS와 Linux에서는 설정 화면에 지원되지 않는 기능으로 표시됩니다.
- 펫 표시/숨기기 전역 단축키는 고정되어 있습니다. 운영체제나 다른 애플리케이션에서 이미 사용 중이면 CacheBite가 해당 단축키를 사용할 수 없다고 표시합니다.
- 하나의 제공자에만 로그인한 경우 다른 제공자는 사용할 수 없는 상태로 표시됩니다.

## 릴리스 엔지니어링

- 태그를 푸시하면 플랫폼별 설치 파일, 체크섬, 서명된 업데이트 파일이 첨부된 GitHub 릴리스 초안이 생성됩니다.
- 릴리스 게시 작업은 수동으로 진행합니다. 릴리스가 초안 상태인 동안에는 업데이터에 새 버전이 표시되지 않습니다.
- 릴리스를 게시하면 `updater` 릴리스에 첨부된 채널 매니페스트가 다시 생성됩니다. 게시되는 모든 릴리스는 `beta.json`을 갱신하므로 베타 사용자는 해당 프리릴리스를 대체하는 안정 버전도 업데이트로 받을 수 있습니다. `stable.json`은 프리릴리스가 아닌 버전을 게시할 때만 갱신됩니다.
- macOS는 아키텍처별 빌드 대신 하나의 Universal DMG로 배포됩니다.
- 서명과 공증이 적용된 macOS 빌드는 보호된 `production-macos-signing` 워크플로 입력을 통해서만 생성됩니다.

## 라이선스

아직 프로젝트 라이선스가 정해지지 않았습니다. 라이선스가 추가되기 전까지 모든 권리는 저작권자에게 있습니다.
